实际修复
1. 金额绑定原文中邻近的币种，避免把“美元、日元、港元、欧元”中的“元”当成人民币。
   本地用例同时覆盖同一句“12美元和20元人民币”、千位分隔、小数、负数及异常逗号。
2. 同一来源中金额相同而币种不同的建议使用不同标识，不再被当作同一项或误报重复。
3. 提示模型只给措辞草稿，不宣称软件已保存、设置、转账、拨号或承诺自动提醒。
   服务会过滤常见中文操作完成声明，明确返回隐藏数量；App 展示说明并再次校验。
   这是有限的文本规则，不等同于完整的语义验证，生成内容仍需用户核对。
4. 无效的新请求清除旧建议；返回格式错误显示内容无效，不再统一误报为网络问题。

日期边界
普通预约中的“明天北京时间下午三点”本次返回 2026-10-28T15:00:00+08:00。
改约中的“后天下午四点”本次仍未解析为完整日期。App 保留原文字并要求用户手动选择，不能声称全自动日期解析已经稳定。
复测标准：能解析时日期须正确；未解析则明确走手动选择。没有把未知时间补成系统当前时间后直接保存。
初版测试按金额字符串比较，误把 18 与 18.00、12 与 12.00 当成不同金额，现改为十进制比较。
初版还把允许的未解析日期回退算作自动解析失败，现将其与解析错误区分。
初版记录保留在 API-Live-Before.json，不能把初版的 3/6 指标解释成只有三次接口请求成功；初版六次 HTTP 均为 200。
